# Standing mail cleanup

You can allow your assistant to perform recurring mail cleanup within a scope you choose. This is optional and inactive until you approve it. You can name the source and destination folders, allow archiving, marking messages read or moving them to recoverable Trash, and choose limits or an expiration date.

Ask your assistant to prepare the proposed scope and review it with you. Activating a scope does not itself change messages. You can ask to inspect or revoke it at any time; revocation stops new batches but cannot recall an action already in progress. An action outside the approved scope needs separate handling.

Standing cleanup does not authorize sending mail, calendar or contact changes, restoring messages, permanent deletion or security changes. It protects starred messages from standing cleanup. The assistant applies your instructions for categories such as newsletters or junk; the server does not independently determine their meaning.

If a cleanup action has an uncertain outcome, ask your assistant to inspect it before continuing. It should not automatically repeat the action. An optional [managed-policy feature](policy-management.md) supports separately reviewed scope changes and exact one-time exceptions.

For tool names, limits and recovery rules, see the [mail cleanup reference](../reference/mail-cleanup.md) and [approval mechanics](../reference/approval-mechanics.md).
