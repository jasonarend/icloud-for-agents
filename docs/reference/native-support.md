# Notes and Reminders support

Notes and Reminders are optional development services on macOS. Each service starts disabled and has independent source selection and access controls. The MCP tools work through the shared server for stdio and private-tunnel clients. A client's ability to connect does not establish that its first-use macOS permission prompts have been tested.

| Workflow | Current implementation | Boundary |
| --- | --- | --- |
| Read today's reminders or a date range | Bounded queries and daily views, including supported filters | The agent schedules and presents briefings; the server does not deliver proactive briefings. |
| Find information in Notes | Scoped title/plaintext searches, bounded reads and exported table text | Locked notes, unavailable exports and incomplete native objects are disclosed. |
| Review a saved native Notes checklist | Optional exact-note pages of native IDs, checked state, indentation, paragraph text and UTF-16 offsets | Reads the bounded stored body after unlocked-note and source checks. Saved local state can lag UI edits; unsaved UI state, rich objects, native checklist writes and cloud freshness remain unverified. |
| Save a product specification or supplied meeting transcript | Reviewed note creation and supported edits; bounded plain list and table HTML formatters | These tools save supplied content. They do not record a meeting or create a native audio transcript. |
| Organize existing content | Notes folder creation/renaming and item moves; Reminder fields/completion, section creation/renaming and bounded leaf membership moves, tags, root-child creation, subtree moves, leaf reparenting/sibling ordering, root ordering, list appearance and bounded empty/populated group organization | Advanced moves use optional native backends and exact private same-account scope. Section membership moves additionally require the optional read-only store guard and a list of at most twenty live items. Populated-group moves require an explicit permission field and preserve existing observed members. Nested families, shared and broader hierarchy mutations remain restricted. |
| Inspect links in Notes | Exported HTML link pages and bounded exact-reference searches in one selected folder | No targets are opened; native backlinks and complete link identity are unverified. |
| Copy supplied observations | Explicitly reviewed lossy Notes or Reminder copies; supported single-VTODO import/export | Copies omit native metadata and can duplicate content. They are not restores or full backups. |
| Delete or restore notes and reminders | Exact same-object Notes moves to verified system Trash and restoration; recoverable Reminder root-leaf or explicitly reviewed direct-family deletion and owned-ledger restoration | Operation-specific role and recovery checks apply. A Reminder family needs explicit descendant inclusion and restores into its original list; manual positions may change. Hidden/inaccessible Notes Trash, deeper hierarchy/section/recurrence effects and container deletion remain restricted. No permanent deletion or empty-Trash operation is exposed. |
| Read native Notes metadata | Optional exact pin, direct native tag/asset observations, bounded pin/tag-filtered physical-folder pages and Smart Folder definitions | These reads do not enable pin/tag/Smart Folder writes or establish complete native semantics or inventories. |
| Organize custom Reminder Smart Lists | Bounded discovery, native JSON definition reads, approved creation, renaming and typed source-list changes for verified Lists-only AND views | Definitions are untrusted data. Renaming preserves raw filter bytes; source changes canonicalize the supported JSON. Creation uses one to ten private ordinary physical references and a preassigned view ID. Arbitrary filters, other criteria, view deletion and general filter evaluation remain unavailable. |
| Assign a grocery reminder to a category | Exact existing category or explicit null removal in one private grocery list; bounded root leaves, native and read-only-store guards, once/scenario permissions | Preserves task content, timestamps, order, bystander memberships and category inventory. Requires both optional backends. Automatic classification, predefined-category configuration, shopping state and cloud atomicity remain unverified. |
| Create a custom grocery category | Exact private grocery list, one preassigned category ID and title, at most twenty incomplete nonrecurring root tasks; once and scenario approvals | Preserves observed task content, manual order and category inventory. No automatic classification or item assignment. Exact category display order, hidden classifier state and cloud synchronization remain unverified. |
| Set an empty list’s grocery categorization | Exact private empty-list flag changes through normal once/scenario approvals; current local UI round trip showed Groceries and Standard | Refuses populated, sectioned, shared, group and shopping-session lists. Locale, classifier suggestions, shopping sessions and manual overrides remain unverified; no atomicity or cloud-sync guarantee. |
| Inspect, rename and create saved Reminder templates | Bounded name-only renaming, native discovery/section/configuration observations, explicitly requested existing sharing-link metadata, and separately opted-in saved-item outlines and exact title/notes text projections with parent links, priority and feature-presence flags | The outline omits bodies; the separate item-details reader projects text and bounded uninterpreted native scheduling/flag values. Neither reconstructs completion, interpreted dates/alarms, attachments or rich metadata; saved item IDs are distinct from live Reminders. Nullable configuration is not reconstructed; source-list references and sharing-link availability are unverified, and links are never fetched. Creation supports only one to nineteen distinct-title incomplete roots with empty notes in a private ordinary unsectioned list, with no scheduling, links, tags, flags, urgent state or rich objects. Quota includes every copied task plus the template. A separate approved text-copy tool can create new incomplete roots from at most ten root saved items in an existing list, explicitly omitting native metadata and scheduling; it can follow a separately approved ordinary list creation. Native instantiation, complete backup and other template writes remain unavailable. Name-only renaming requires the explicit read-only store guard, no observed public link and at most twenty saved items. |
| Read printed text in an image attachment | Bounded derived English OCR from one exact PNG/JPEG export using bundled Apple Vision processing | Updated helper, unlocked note and selected source required. At most 128 KiB/eight million pixels; explicit confidence and truncation. Native Notes OCR/index, handwriting and document layout are not reconstructed. |
| Export attachments | Bounded Notes native-file exports, separate generated-PDF reads and local Reminder image/file representations | At most 1 MiB per file; local availability and exact scope are required. Converted representations are identified; complete backups and original-byte fidelity are not assumed. |
| Edit rich native Notes objects | Supported basic HTML/text edits and bounded exported observations | Native checklist, pin/tag/Smart Folder mutation, rich object editing, sharing changes and password operations remain unavailable. |

Supported writes use the existing one-time approval or explicitly scoped ongoing/scenario grants. Effective service access, selected sources, target identity, content-preservation checks and unfinished-write guards apply at execution. An OS grant does not enable application writes. A supplied observation or generated HTML does not authorize saving it.

Use `notes_access_status` or `reminders_access_status` for the current implementation inventory and unavailable-operation reasons. These local reports do not probe provider support or grant authorization. The optional private native backends have additional interface and preservation requirements; their presence does not guarantee every operation on every object.

The status result's `unavailable_feature_families` also lists the advanced routes that cannot currently be completed through MCP. Permission elevation cannot enable them. Notes folder reparenting is among these: a synthetic empty-folder experiment returned an error and left the source marked deleted. No notes were in it, restoration was not established, and no fresh folder-move writer is exposed. Notes native checklist/pin/tag/Smart Folder writers, rich attachment/object editing, native OCR/handwriting, recording/transcript objects, collaboration and password operations remain unavailable. Reminders rich template creation, template content editing/deletion/instantiation, arbitrary Smart List filters, populated grocery conversions and automatic classification, deeper hierarchy/group moves, section ordering/deletion, attachment writes, collaboration and special person/vehicle triggers remain unavailable. Container deletion and permanent purge are not exposed for either service. Supported bounded item removal/restoration is described above; it does not establish container or arbitrary historical recovery.

Local synthetic tests cover protocol, approval, scope, bounds and failure behavior. Individual live observations and their limits are described in the [native service guide](../getting-started/native-services.md). Native HTML rendering, cross-device synchronization, first-use prompt attribution across clients and the complete advanced-feature set do not have blanket acceptance. A build or passing synthetic test does not establish those behaviors.

For setup, exact tool options and operation-specific evidence, use the [native service guide](../getting-started/native-services.md). Keep a failed or uncertain write's audit and inspect its retained evidence before further work; do not replay the request or clear its guard based only on an apparently unchanged object.
